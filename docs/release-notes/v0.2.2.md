# v0.2.2

Patch release for AWS public-identity lifecycle and gateway interface support.

## What Changed

- Added `eip_allocation_ids` so module users can pass independently managed EIP
  allocation IDs per availability zone. BetterNAT never releases these EIPs.
- Added `retain_managed_eips_on_destroy` for migration from existing
  provider-managed EIPs and same-name gateway recreation.
- Added `primary_interface` and `snat_interface` overrides, both defaulting to
  provider-side automatic detection.
- Added module checks that reject external EIPs when stable egress is disabled
  and reject allocation IDs for availability zones outside `azs`.
- Raised the minimum BetterNAT provider version to `0.2.2`.

## Recommended Migration

For an existing module-managed gateway, apply
`retain_managed_eips_on_destroy = true` before replacement. Import the retained
allocation into an independent `aws_eip`, pass it through
`eip_allocation_ids`, and then perform the planned gateway replacement.

New production deployments should start with independent `aws_eip` resources,
normally protected by `prevent_destroy`.
